# ФинРитм

> **Демо-режим. Все данные вымышлены. Не является финансовой рекомендацией.**

ФинРитм — помощник для студентов с нерегулярным доходом: стипендия приходит 5-го, подработка — 10-го, а аренда списывается 1-го.
Он строит календарь до следующего поступления и показывает, сколько можно безопасно тратить в день, влезет ли покупка и почему.
Все суммы считает код, а не нейросеть; каждый ответ объясняет, из каких чисел он получен, какие допущения сделаны и чего не хватает в данных.

- **Сайт:** _адрес появится после деплоя (задача Вероники VF3)_
- **API и интерактивная документация:** `https://<адрес>/docs` · локально — http://localhost:8000/docs

## Быстрый старт

Нужны Git и Docker **или** Python 3.12.

```bash
git clone https://github.com/whatreallifeis/FinRythm.git
cd FinRythm
cp .env.example .env            # Windows (PowerShell): copy .env.example .env
docker compose up --build
```

Откройте http://localhost:8000/docs — это API с кнопкой «Try it out» у каждого запроса.
Ключи и токены для запуска не нужны: по умолчанию `LLM_PROVIDER=fake` (помощник работает без нейросети), `APP_TODAY=2026-09-26` (дата демо, при ней сходятся числа ниже).

**Без Docker:**

```bash
python -m venv .venv
source .venv/bin/activate        # Windows (PowerShell): .venv\Scripts\Activate.ps1
pip install -r requirements.txt -r requirements-dev.txt
cp .env.example .env
uvicorn app.main:app --reload --app-dir backend
```

## Как проверить за 2 минуты

Сценарий: студент загружает демо-данные, смотрит календарь до стипендии и спрашивает, можно ли сегодня купить телефон за 14 900 ₽.
Команды для bash (Linux, macOS, Git Bash на Windows). Все эндпоинты и форматы видны в http://localhost:8000/docs, но запросы с входом удобнее делать так: токен из первого шага передаётся в заголовке `Authorization: Bearer …`.

```bash
API=http://localhost:8000/api
# 1. Демо-вход и демо-данные: баланс 18 430 ₽, стипендия 8 000 ₽ 5-го, подработка 25 000 ₽ 10-го, операции за 2 месяца
TOKEN=$(curl -s -X POST $API/auth/demo | sed 's/.*"token":"\([^"]*\)".*/\1/')
AUTH="Authorization: Bearer $TOKEN"
curl -s -X POST $API/demo/seed -H "$AUTH"

# 2. Календарь до следующего поступления
curl -s $API/analysis/runway -H "$AUTH"

# 3. Можно ли сегодня потратить 14 900 ₽?
curl -s -X POST $API/analysis/impulse -H "$AUTH" -H "Content-Type: application/json" -d '{"amount": 14900}'

# 4. Тот же вопрос помощнику своими словами
#    (тело — через stdin: так русский текст доходит в UTF-8 и в Git Bash на Windows)
curl -s -X POST $API/ask -H "$AUTH" -H "Content-Type: application/json" --data-binary @- <<'JSON'
{"question": "Хочу купить телефон за 14 900 ₽. Можно сегодня?", "scenarioId": "impulse"}
JSON
```

Что должно получиться (дата расчёта 26.09.2026):

| Шаг | Результат |
|---|---|
| Календарь | до «Стипендии» 5 октября — 9 дней; обязательные платежи до неё 14 148 ₽ (аренда 12 000, проездной 1 200, подписки 299 и 649); **можно тратить 475 ₽ в день**: (18 430 − 14 148) ÷ 9; минимальный остаток 4 282 ₽, красных дней нет |
| Покупка 14 900 ₽ | `verdict: shortfall` — **не влезает**: лимит падает с 475 до 0 ₽, баланс уходит в минус до −10 618 ₽, 9 красных дней; безопаснее подождать «Подработку» 10 октября; цель «Ноутбук для учёбы» сдвинется примерно на 36 дней |
| Для сравнения | 3 000 ₽ → `wait` (лимит 142 ₽, лучше после стипендии 5 октября); 500 ₽ → `ok` (лимит станет 420 ₽) |
| Помощник | «Сейчас покупка на 14 900 ₽ не влезает: после обязательных платежей баланс уйдёт в минус — до −10 618 ₽. Безопаснее подождать поступления «Подработка» 10 октября…» + те же шаги расчёта и допущения |

Каждый аналитический ответ приходит в обёртке `Explained`: `result` (сам ответ), `calculation` (шаги расчёта с формулами), `assumptions`, `sources`, `limitations` и `dataQuality` (хватает ли данных и чего не хватает).

Ещё вопросы помощнику (`POST /api/ask`, поле `scenarioId`): `budget` — «Хватит ли мне денег до конца месяца?», `expenses` — «Куда уходят мои деньги?», `glossary` — «Что такое инфляция?», `free` — любой вопрос, и «Взять микрозайм до стипендии?» — чтобы увидеть отказ с объяснением и ссылкой на Банк России.

## Входные данные

- **Демо-профиль студента** — `data/demo/student.json` (формат `UserState` из `backend/app/models.py`), загружается `POST /api/demo/seed`. Все данные синтетические.
- **Свои данные:** баланс и регулярные поступления — `PUT /api/profile`; операции — `POST /api/transactions/import` строками `{date, amount, category, merchant}` (CSV разбирает фронтенд; до 5 000 строк, отчёт о принятых и отклонённых строках); цели — `POST /api/goals`.
- Все форматы — в [`contracts/api.md`](contracts/api.md) и [`contracts/data_formats.md`](contracts/data_formats.md).
- Если данных не хватает, API не выдумывает: отвечает `dataQuality.sufficient = false` и перечисляет, чего не хватает («текущий баланс», «операции хотя бы за один месяц»).

## Как считается дневной лимит

Календарь идёт от сегодня до следующего поступления. Обязательные платежи (аренда, связь, проезд, подписки — операции, которые повторяются каждый месяц) ставятся на свои даты.

```
можно тратить в день = (баланс − обязательные платежи до поступления) ÷ дней до поступления   (вниз до рубля)
```

Пример демо-профиля: (18 430 ₽ − 14 148 ₽) ÷ 9 дней = 475 ₽ в день.
Проверка покупки прогоняет тот же календарь с покупкой сегодня: смотрит лимит после покупки, минимальный остаток и «красные» дни с отрицательным балансом, а если сейчас нельзя — ищет ближайшее поступление, после которого покупка безопасна.
Все деньги внутри — `Decimal`, в JSON — числа в рублях.

## Роль AI

| Что делает | Кто |
|---|---|
| Суммы, проценты, даты, лимиты, вердикты | **код** (`backend/app/core`) — нейросеть ничего не считает |
| Выбор сценария, текст ответа вокруг готовых чисел | помощник (`backend/app/ai`) |
| Объяснение терминов | только по проверенной базе знаний `data/knowledge_base/kb.json` (Банк России, «Финансовая культура») с источником в ответе; термина нет в базе — помощник так и говорит |
| Рискованные запросы: инвестиции, крипта, кредиты, ставки, переводы денег, «реши за меня», номера карт и коды из СМС | отклоняются **до** расчётов и до нейросети — с объяснением и ссылкой на источник |

- **Режим `fake`** (по умолчанию, ключ не нужен): текст собирается по шаблонам только из чисел расчёта. На нём работает демо.
- **Реальная модель** (`LLM_PROVIDER=openai_compat`) будет только переформулировать текст вокруг тех же чисел; ответ проходит проверку: каждое число в тексте должно быть в результатах расчёта, иначе — шаблонный ответ.
- Поиск по базе знаний — BM25 (`rank-bm25`) по заголовку, ключевым словам и тексту.

## Структура репозитория

```
backend/app/
  api/        HTTP API на FastAPI, вход, ошибки, сериализация        — Вероника
  storage/    SQLite: сессии и данные пользователя                   — Вероника
  core/       все расчёты: календарь, покупка, прогноз, обзор, цели  — Саша
  ingest/     импорт операций                                        — Саша
  ai/         помощник: сценарии, фильтр рисков, база знаний, LLM    — Соня
  models.py   модели данных (контракт)
backend/tests/   тесты по зонам (core, ai, api)
tests/e2e/       сквозные тесты по HTTP                              — Саша
contracts/       API, форматы данных, эталонные числа
data/demo/       демо-профиль;  data/knowledge_base/  база знаний    — Соня
docs/            ТЗ, процесс, архитектура, ограничения
```

Команда: **Вероника** — API, хранилище, инфраструктура; **Саша** — финансовые расчёты, импорт, сквозные тесты; **Соня** — AI-помощник, база знаний, документация; фронтенд — **ruina696**.
Подробнее — [`docs/architecture.md`](docs/architecture.md).
