## 2. Как Claude Code связаны между собой

Сессии Claude Code не видят друг друга напрямую. Связь идёт через репозиторий — это и есть «общая память» команды:

| Канал | Что там | Как Claude использует |
|---|---|---|
| `CLAUDE.md` | Общие правила, карта зон, команды | Claude Code читает автоматически при запуске в папке репозитория |
| `contracts/` + `backend/app/models.py` | Модели, API, форматы, эталонные числа | Источник правды: код обязан ему соответствовать |
| `docs/tasks/<имя>.md` | Персональное ТЗ | Claude читает при старте и берёт следующую задачу по порядку |
| `docs/status/<имя>.md` | Что сделано, что в работе, что заблокировано, что нужно от других | Claude обновляет в конце каждой задачи; перед началом новой задачи читает статусы остальных |
| **GitHub Issues** с метками `to:veronika`, `to:sasha`, `to:sonya`, `to:kira` | Запросы между зонами: «нужно поле», «нашёл баг в твоём модуле», «добавь зависимость» | Перед каждой задачей: `gh issue list --label to:<я> --state open`. Создать запрос: `gh issue create --label to:sasha --title "..." --body "..."` |
| **Pull Requests** | Код, CI, история | `gh pr create --fill` → `gh pr merge --squash --delete-branch` без ревью |
| Заглушки | Каждый модуль сначала отдаёт рабочую заглушку с правильными типами | Никто не ждёт другого: API работает на заглушках core и fake-AI, бот — на API с заглушками |

**Правило «не трогай чужую зону»:** Claude меняет файлы только в своей зоне. Нужна правка в чужой — issue владельцу. Исключение — срочный однострочный фикс с согласия владельца в чате.

**Изменение контрактов** (`models.py`, `contracts/*`): отдельный PR с меткой `contract`, перед мержем — issue `to:veronika` со ссылкой, после мержа — сообщение в общий чат команды. Ждать ревью не нужно. Добавлять необязательные поля можно быстро, удалять и переименовывать — только всем вместе на синхронизации.

## 3. Git-процесс

- Каждый работает **только в своей ветке**. Закончил задачу — сам вливает её в `main` через PR: CI зелёный, одобрение не нужно. Незаконченную работу в `main` не вливаем.
- Ветка задачи: `<имя>/<id>-<кратко>` → `sasha/S2-runway`, `sonya/A4-guardrails`.
- Коммиты — Conventional Commits, область = зона: `feat(core): расчёт дневного лимита`, `fix(api): формат ошибки валидации`, `test(e2e): сценарий дефицита`, `docs(readme): инструкция запуска`.
- Маленькие PR: одна задача = один PR, желательно ≤ 400 строк.
- Перед пушем: `git fetch origin && git rebase origin/main && pytest && ruff check .`
- Мерж: **Squash and merge**. После мержа — удалить ветку.
- Ревью нет: Саша и Соня вливают свои PR сами. Вероника может посмотреть любой PR уже после мержа и завести issue, если что-то не так.

## 6. Граф зависимостей (кто кого ждёт — и почему не ждёт)

```
contracts/, models.py (готовы в Ч0) ─┬─► Саша: core ──────────► Соня: tools ─► orchestrator
                                     │        │                                   │
                                     │        └──► Вероника: API ◄─────────────────┘
                                     │                  ▲
                                     └─► Кирилл: demo-данные, KB ──► Соня: RAG
                                                        │
                                  Кирилл: бот, e2e ─────┘ (через HTTP)
```

Чтобы никто не простаивал:
- Саша за первые 30–40 минут вливает **заглушки** всех функций core (правильные типы, данные P1) → Вероника и Соня сразу подключают.
- Соня в первый час вливает **fake-провайдер** → чат работает без ключа.
- Вероника к Ч1:30 вливает API на заглушках → Саша пишет e2e против настоящих URL.
- Демо-профили уже лежат в `contracts/profiles/` → все тестируют на них с первой минуты.

## 7. Если что-то пошло не так

| Ситуация | Действие |
|---|---|
| Нет ключа LLM к Ч3 | Демо на `fake`, Соня продолжает всё остальное; честно говорим на защите |
| Кончился лимит подписки Claude у человека | Человек продолжает вручную или берёт QA; задачи переносятся в issue на того, у кого меньше нагрузки |
| Конфликт в `main` | Автор PR делает `git rebase origin/main`, решает конфликт только в своих файлах; в чужих — зовёт владельца |
| Сломался прод | Вероника откатывает на последний зелёный коммит (`git revert`), разбор после |
| Эталонное число не сходится | Прав `contracts/reference_runway.py`. Если ошибка в эталоне — PR `contract` с объяснением, всем сообщение |
