# Архитектура ФинРитм

## Компоненты

```
 Сайт / Telegram Mini App (фронтенд ruina696, позже)
                 │  HTTPS, JSON, Authorization: Bearer <token>
                 ▼
        backend/app/api  (FastAPI)  ─── storage (SQLite: сессии + данные пользователя)
          │        │          │
          │        │          └──► ai  (помощник) ──► LLM-провайдер (fake | openai_compat)
          │        │                │   │
          │        └──► core ◄──────┘   └──► rag ◄── data/knowledge_base/kb.json
          │          (все расчёты)
          └──► ingest (импорт операций)
```

| Модуль | Что делает | Владелец |
|---|---|---|
| `backend/app/api` | эндпоинты `/api/*`, вход (демо и Telegram), ошибки по-русски, перевод `Decimal` → число на границе JSON | Вероника |
| `backend/app/storage` | SQLite: сессия → `UserState` одним JSON | Вероника |
| `backend/app/core` | календарь до поступления, проверка покупки, прогноз до конца месяца, обзор трат, план цели; чистые функции на `Decimal`, каждая возвращает `Explained` | Саша |
| `backend/app/ingest` | импорт строк операций, отчёт об отклонённых | Саша |
| `backend/app/ai` | `ask()`: фильтр рискованных запросов, сценарии, база знаний, текст ответа | Соня |
| `backend/app/models.py` | модели данных — общий контракт | Вероника |

**Правило зависимостей:** `core` зависит только от `models`; `ai` — от `core` и `models`; `api` — от всех. Фронтенд и бот ходят только по HTTP.

## Как обрабатывается вопрос помощнику

`POST /api/ask {"question": "Хочу купить телефон за 14 900 ₽. Можно сегодня?", "scenarioId": "impulse"}`

1. **API** проверяет токен и лимит (20 вопросов в минуту), достаёт данные пользователя и вызывает `ai.ask(question, scenario_id, state, as_of, llm=..., kb=...)`.
2. **Фильтр рискованных запросов** (`ai/guardrails.py`) — правила по намерению. Сработал («взять микрозайм», «куда вложить», номер карты) — сразу отказ с объяснением и источником из базы знаний; расчёты и нейросеть не вызываются.
3. **Выбор сценария.** `impulse`, `budget`, `expenses`, `glossary` — как прислал фронтенд; `free` — ближайший сценарий по словам вопроса, иначе просьба уточнить.
4. **Данные из вопроса.** Для `impulse` — сумма: «14 900 ₽», «3к», «2,5 тыс» (`ai/amounts.py`). Нет суммы — `sufficient = false`, «сумма покупки».
5. **Расчёт в core.** `check_impulse(state, 14900, as_of)` прогоняет календарь с покупкой и возвращает `Explained`: вердикт, лимит до и после, минимальный остаток, красные дни, до какого поступления подождать, шаги расчёта, допущения.
6. **Текст ответа** (`ai/scenarios.py`) собирается вокруг этих чисел на «вы»; шаги расчёта, допущения, ограничения и `dataQuality` переносятся из core без пересчёта.
7. Для `glossary` вместо расчёта — **поиск в базе знаний** (`ai/rag.py`, BM25). Ответ — только текст фрагмента и его источник; ниже порога — «проверенного источника нет».
8. **API** переводит ответ в JSON (camelCase, деньги — числа). Историю диалогов сохраняет фронтенд через `PUT /api/history/{id}`.

С реальной моделью (AF5) между шагами 6 и 8 появится LLM, который переформулирует текст; проверка чисел сравнит каждое число ответа с результатами расчёта и при расхождении вернёт шаблонный текст из шага 6.

## Данные

- `UserState`: баланс, регулярные поступления (`dayOfMonth`), цели, операции (`isRecurring` — повторяется каждый месяц).
- Дата расчёта — `APP_TODAY` (демо: 2026-09-26) или сегодня.
- Эталонные числа демо — `backend/tests/core/test_front_calc.py`; сквозной сценарий — `tests/e2e/`.
