# Форматы данных

## 1. CSV с операциями (импорт)

Владелец парсера: **Саша** (`backend/app/ingest/csv_import.py`). Примеры файлов: **Кирилл** (`data/samples/`).

```csv
date,amount,description,category
2026-09-20,-450.00,МТС связь,Связь
2026-09-21,3500.00,Оплата за смену,Подработка
2026-09-22,-289.00,Пятёрочка,
```

| Колонка | Обязательна | Правило |
|---|---|---|
| `date` | да | `ГГГГ-ММ-ДД`. Также принимается `ДД.ММ.ГГГГ`. Дата не позже `as_of` + 1 день |
| `amount` | да | Число, разделитель — точка или запятая, пробелы внутри числа допускаются (`-1 200,50`). Расход со знаком минус. 0 — ошибка |
| `description` | да | 1–200 символов |
| `category` | нет | Если пусто — автокатегоризация по словарю (`backend/app/core/categories.py`) |

- Кодировка UTF-8 (с BOM или без). Разделитель — запятая или точка с запятой (определять автоматически).
- Лишние колонки игнорируются, отсутствие обязательной колонки — ошибка всего файла.
- Дубликат = совпадают `(date, amount, description)` с уже существующей операцией → не добавляется, считается в `duplicates`.
- **Защита данных:** если в любой ячейке есть 16 цифр подряд (с пробелами или без) — строка отклоняется с сообщением «Похоже на номер карты. Не загружайте реальные банковские данные».
- Ошибочные строки не блокируют файл: они попадают в `ImportReport.errors` с номером строки (заголовок — строка 1).
- Лимиты: до 5 000 строк, до 1 МБ.

## 2. Категории

Расходы: `Продукты`, `Кафе и доставка`, `Транспорт`, `Связь`, `Подписки`, `Жильё`, `Развлечения`, `Одежда`, `Здоровье`, `Образование`, `Переводы`, `Другое`.
Доходы: `Стипендия`, `Подработка`, `Семья`, `Другое`.

## 3. База знаний (RAG)

Владелец контента: **Кирилл** (`data/knowledge_base/kb.json`). Владелец поиска: **Соня** (`backend/app/ai/rag.py`).

```json
[
  {
    "id": "kb-001",
    "title": "Финансовая подушка безопасности",
    "text": "Финансовая подушка — запас денег на случай непредвиденных ситуаций... (80–250 слов, своими словами, без копирования больших фрагментов)",
    "keywords": ["подушка", "резерв", "запас", "непредвиденные расходы"],
    "source_title": "Банк России, «Финансовая культура»",
    "url": "https://fincult.info/...",
    "checked_at": "2026-09-26"
  }
]
```

- Только публичные проверенные источники: Банк России (cbr.ru, fincult.info), Минфин (моифинансы.рф), тексты законов (consultant.ru, garant.ru), официальные сайты госорганов. **Не использовать** блоги, форумы, «правила Т-Банка».
- Каждый `url` открывается и проверяется **человеком** (Кириллом) — ИИ может выдумать ссылку.
- Объём: 40–60 фрагментов. Обязательные темы: подушка безопасности, бюджет, обязательные и переменные расходы, ключевая ставка, инфляция, процент по вкладу, сложный процент, кредит и полная стоимость кредита (ПСК), кредитная карта и льготный период, микрозаймы и их риски, мошенничество (социальная инженерия, коды из SMS), самозанятость и налог на профессиональный доход, стипендия (виды), налоговый вычет за обучение, страхование вкладов (АСВ), подписки, импульсивные покупки, финансовые пирамиды, инвестиционные риски (общее, без рекомендаций), кешбэк.

## 4. Демо-профили

- Базовые данные (без операций): `contracts/profiles/p1.json`, `p2.json`, `p3.json` — **менять нельзя**, на них построены эталонные результаты.
- Полные демо-профили с операциями за 60 дней: `data/demo/p1.json` … — генерирует Кирилл скриптом `scripts/generate_demo.py` (seed = 42). Поля `balance`, `incomes`, `payments`, `goals`, `settings`, `as_of` копируются из `contracts/profiles` без изменений.
- Обязательные закономерности в сгенерированных операциях (на них опираются тесты рисков и структуры):
  - P1: ежемесячно «Подписка на музыку» −299 (2026-08-05, 2026-09-05); одна аномальная трата «Кроссовки» −6 990 в категории «Одежда» при остальных тратах категории ≤ 1 500.
  - P3: ежемесячно «Подписка на музыку» −299 (2026-08-07, 2026-09-07) и «Подписка на кино» −299 (2026-08-12, 2026-09-12).
  - Все даты операций — с 2026-07-28 по 2026-09-25 включительно.
- После генерации эталонные значения структуры расходов и рисков фиксируются в `contracts/expected_breakdown.json` (Кирилл запускает функции Саши, Саша проверяет числа вручную на 2–3 категориях, оба подтверждают в PR).
